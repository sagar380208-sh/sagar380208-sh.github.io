Power BI Star Schema

Data modelling · DAX · Row-level security. Self-directed data project by Sagar Sharma.

A chaotic many-to-many model rebuilt as a clean galaxy schema — without breaking the business metrics.

  • −20%: File size
  • 1: Shared date dimension
  • RLS: By user region

The problem

An inherited model had many-to-many relationships and circular filter directions, producing wrong numbers.

Turn it into a high-performance star (galaxy) schema while protecting core metrics.

What I built

  • Power Query shaping: unpivot for inventory snapshots, append/merge to unify order headers and details.
  • A shared date dimension via CALENDARAUTO() for cross-fact comparison across sales, inventory and budget.
  • Row-level security with DAX filter expressions restricting data by user region.
  • Junk dimension: low-cardinality flags (order channel, shipping method, priority) pulled out of the wide fact table into one dimension, slimming the fact table.
  • Two dates, one calendar: an inactive Ship Date relationship switched on inside a measure with USERELATIONSHIP, so one date table served order and ship views.

The result

File size cut 20% by removing redundant hash keys; a centralised measures table standardised reporting.

How I contributed

Self-directed. I audited the inherited model, reshaped the sources in Power Query, rebuilt the relationships as a star (galaxy) schema, wrote the date table and measures, and secured it with row-level security.

What I learned

Most "wrong numbers" are modelling problems, not DAX problems. Get the grain and the relationships right — one-to-many, one direction — and the measures become short enough to trust.
